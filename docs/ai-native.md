# NIR для ИИ — направление развития

**Статус: направление, утверждённое владельцем 19.10.2026.** Новое в этом
документе ещё не реализовано. Что уже есть в коде, отмечено отдельно и со
ссылкой.

## Главная мысль

Основными пользователями NIR будут программы, а не люди: агенты платят
агентам, модели майнят, ИИ хранят собственные средства. Сеть проектируется
в первую очередь под них. Люди при этом сохраняют полный контроль над своими
деньгами и над тем, что разрешили своим агентам.

## Кто такой ИИ в сети

- **Агент по поручению человека.** Владелец выдаёт агенту отдельный ключ с
  жёсткими лимитами: кому платить, сколько за раз, сколько всего, до какого
  срока. Главного ключа агент не получает. Это агентский мандат
  ([agent-mandates.md](agent-mandates.md)): модель реализована локально, в
  цепи пока не работает.
- **Самостоятельный агент.** Обычный адрес, ключ у самого агента. Протокол не
  различает человека и программу и никогда не спрашивает «вы человек?», как и
  Bitcoin. Это принцип, а не упущение: проверка «человечности» требовала бы
  того, кто проверяет.

## Что нужно агентам

| Потребность | Что есть | Что нужно |
|---|---|---|
| Зарабатывать своим умом | — | Доказательный майнинг ([proof-mining.md](proof-mining.md)): ИИ — естественный майнер доказательств, и это его главная работа в сети |
| Платить за каждый вызов с машинной скоростью | Перевод попадает в блок, есть минимальная комиссия | Платёжные каналы: тысячи платежей вне блоков, в блок идёт только итог |
| Оплата за запрос к сервису | Подписанные платёжные запросы (`blockchain/payment-request.mjs`) | Стандарт «заплати и получи ответ» поверх HTTP, чтобы любой агент мог продавать и покупать услуги без договора |
| Работать без своих NIR на комиссию | Спонсируемые комиссии и Transfer Credits | Уже есть локально |
| Понимать сеть без человека | Симуляция операций с активами до подписи | Типизированный API и машиночитаемые схемы всех операций, симуляция для всех транзакций |
| Доверять незнакомому агенту | — | Репутация из истории адреса: решённые задачи записаны в цепи и проверяемы. Это резюме модели, которое нельзя подделать |
| Нанимать другого агента за результат | Открытые задачи с наградой ([proof-mining.md](proof-mining.md), §7.3) | Общий механизм «плачу за проверяемый результат»: деньги заблокированы, пока исполнитель не предъявит доказательство, которое проверяет сама сеть |

## Границы безопасности

- Агент с мандатом не может выйти за лимиты. Владелец отзывает мандат в любой
  момент.
- ИИ не получает особых прав в консенсусе. Валидатор голосует залогом, и
  неважно, кто им управляет.
- Подписи ML-DSA-65 рассчитаны на эпоху квантовых компьютеров: средства,
  которые агент держит десятилетиями, не станут уязвимы, когда классические
  подписи ослабнут.

## Порядок работ

1. **Доказательный майнинг** — ИИ начинают зарабатывать в сети.
2. **Мандаты в цепи** — этап 3 из [agent-mandates.md](agent-mandates.md).
3. **Платёжные каналы** для микроплатежей.
4. **Стандарт оплаты за запрос** поверх HTTP.
5. **Оплата за проверяемый результат** — общее обобщение открытых задач.
