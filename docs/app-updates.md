# Кнопка «Обновить» в NIR Wallet и NIR Model Lab

Оба приложения для Mac обновляются сами: **Настройки → Проверить обновления →
Обновить до X**. Приложение скачивает новую версию, собирает её, закрывается и
открывается уже обновлённым. Файлы и ключи кошелька при этом не меняются.

Новую версию разрешает только **ключ выпусков владельца NIR**. Адрес этого
ключа записан в самом установленном приложении
(`blockchain/update-trust-anchor.mjs`). Поэтому обновление нельзя подсунуть,
даже взломав GitHub: без подписи владельца приложение его не поставит.

## Один раз: создать ключ выпусков

На своём Mac, в папке NIR:

```sh
npm run app-release:key
```

Команда:

- спросит пароль (не короче 12 символов);
- создаст зашифрованный ключ в `~/.nir/release-signer.nirvault.json`;
- впишет адрес ключа в `blockchain/update-trust-anchor.mjs`.

Дальше:

1. Сохраните файл ключа и пароль где-то ещё, кроме этого Mac. Потеря ключа
   означает, что приложения больше не примут обновлений: их придётся
   пересобрать вручную с новым ключом.
2. Закоммитьте и запушьте изменение `update-trust-anchor.mjs` в `main`.
3. Один раз соберите оба приложения вручную из этого коммита
   (`npm run wallet:macos-build` и `npm run mine:macos-build`). Эти сборки
   уже знают ваш ключ, и дальше обновляются кнопкой.

## Каждый выпуск: одна команда

Когда в `main` есть новая версия, на Mac:

```sh
git checkout main && git pull
npm run app-release:sign
```

Команда спросит пароль ключа, подпишет текущий `main` и запушит файл
`releases/source-release.json`. После этого у всех кнопка «Проверить
обновления» покажет новую версию.

Команда откажется подписывать, если:

- есть незакоммиченные изменения;
- локальная ветка не совпадает с `origin/main`;
- ключ не тот, что записан в коде;
- с прошлого выпуска ничего не изменилось.

## Что делает кнопка

1. `git fetch` ветки `main` из той копии репозитория, из которой приложение
   было собрано. Рабочие файлы и ветки этой копии не трогаются: всё уходит в
   отдельную ссылку `refs/nir-update/main`.
2. Проверяет подпись `releases/source-release.json` закреплённым адресом.
   Номер выпуска должен быть больше установленного, поэтому откатить на старую
   версию нельзя.
3. Убеждается, что подписанный коммит входит в `main`, и выгружает ровно его
   (`git archive`) во временную папку рядом с приложением.
4. Собирает новое приложение тем же Node.js (и Python для Model Lab), которыми
   было собрано установленное.
5. Закрывает приложение, ставит новое на его место и открывает. Прежняя версия
   остаётся в папке `.nir-update-…` рядом с приложением, на случай отката
   вручную.

Если сеть недоступна, подпись не сходится или сборка упала, установленное
приложение не меняется, а на экране видна причина.

## Ограничения

- Пока это обновление сборок из исходного кода: на Mac нужны git, Node.js 26+,
  инструменты Xcode, а для Model Lab — Python. Для публичного выпуска понадобятся
  готовые сборки с подписью Apple (Developer ID) и нотаризацией. Подписанный
  каталог готовых сборок уже есть (`blockchain/update-catalog.mjs`), и он
  проверяется тем же закреплённым ключом.
- Коммит связан с содержимым через хэш git (SHA-1 с защитой от коллизий).
- Если репозиторий приватный, у пользователя должен быть к нему доступ в git.
- Код: `blockchain/source-release.mjs` (формат и подпись),
  `blockchain/source-updater.mjs` (кнопка), `blockchain/app-release-cli.mjs`
  (команды владельца). Тест: `tests/app-updates.test.mjs`.
