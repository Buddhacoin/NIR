# Кнопка «Обновить» в NIR Wallet и NIR Model Lab

Оба приложения для Mac обновляются сами: **Настройки → Проверить обновления →
Обновить**. Больше ничего делать не нужно: ни ключей, ни команд, ни поиска
папок. Файлы и ключи кошелька при обновлении не меняются.

## Что происходит при нажатии

1. Приложение держит собственную копию открытого кода NIR в
   `~/Library/Application Support/NIR Updates/` и скачивает в неё ветку
   `main` с https://github.com/Buddhacoin/NIR.
2. Если в `main` есть коммиты новее установленной сборки, на экране появляется
   «Доступна новая версия … от <дата>» и кнопка «Обновить». Версию старее
   установленной приложение не предлагает.
3. «Обновить» выгружает ровно этот коммит (`git archive`) во временную папку
   рядом с приложением и собирает из него новое приложение. Сборка идёт тем же
   Node.js (и Python для Model Lab), которыми было собрано установленное.
4. Приложение закрывается, внутри той же папки приложения старое содержимое
   меняется на новое, и оно открывается. Сама папка не меняется, поэтому ярлык
   на рабочем столе, значок в Dock и Launchpad открывают уже новую версию.
   Прежняя версия лежит рядом в `.nir-update-…`, пока новая не запустится, —
   на случай отката.

Если сети нет или сборка упала, установленное приложение не меняется, а на
экране видна причина.

Сборки, сделанные до появления кнопки, обновляться сами не умеют. Их нужно один
раз собрать заново, дальше хватает кнопки.

## Кому доверяет кнопка

Сейчас — ветке `main` репозитория NIR на GitHub. Код открыт, каждая версия —
это конкретный коммит, и приложение собирает ровно его. Значит, защита
обновлений держится на том, кто может писать в `main`. Включите на GitHub
двухфакторную защиту аккаунта и защиту ветки `main`.

## Дальше: выпуски без единого хозяина

Чтобы сеть пережила создателя, право выпускать версии не должно зависеть от
одного человека или одного аккаунта. Для этого кнопка уже умеет работать в
строгом режиме: если в коде закреплён адрес подписанта выпусков
(`blockchain/update-trust-anchor.mjs`), приложения ставят только выпуски с его
подписью из `releases/source-release.json`. Номер выпуска должен расти,
поэтому откатить на старую версию нельзя. Следующий шаг — сделать подписантом
не одного человека, а набор независимых участников сети (как ключи выпусков
протокола в `docs/protocol-upgrades.md`).

Инструменты строгого режима для разработчиков: `npm run app-release:key`
(закрепить подписанта) и `npm run app-release:sign` (подписать текущий
`main`). Обычным пользователям они не нужны.

## Ограничения

- Пока это обновление сборок из исходного кода: на Mac нужны git, Node.js 26+
  и инструменты Xcode, а для Model Lab — Python. Для публичного выпуска
  понадобятся готовые сборки с подписью Apple (Developer ID) и нотаризацией;
  подписанный каталог готовых сборок уже есть (`blockchain/update-catalog.mjs`).
- Коммит связан с содержимым через хэш git (SHA-1 с защитой от коллизий).
- Код: `blockchain/source-updater.mjs` (кнопка), `blockchain/source-release.mjs`
  и `blockchain/app-release-cli.mjs` (строгий режим). Тест:
  `tests/app-updates.test.mjs`.
