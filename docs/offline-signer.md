# Изолированная подпись

`offline:sign` — отдельный минимальный процесс для ключа. Он не запускает сервер, не делает RPC-запросов, не загружает код и не отправляет операции. Вход — только подготовленный канонический файл, стандартный ввод или текст, собранный из QR-фрагментов другим устройством. Выход — новый закрытый файл с подписью; отправка всегда остаётся отдельным ручным действием на устройстве с сетью.

## Что переносится между устройствами

Подписываемый пакет имеет формат `nir-offline-signing-package-v1`, версию `1` и ровно следующие поля:

`format`, `version`, `createdAt`, `expiresAt`, `networkId`, `intent`, `simulation`, `simulationCommitment`, `checkpoint`.

`simulation` включает исходные доказанные состояния и полный результат симуляции. Изолированный процесс повторно декодирует известный тип, заново строит последствия и сверяет хеш обязательства. Он также требует точного совпадения сети, высоты, хеша вершины и корня состояния с checkpoint. Неизвестное поле, тип или версия, просроченный пакет, изменённый nonce, повторно использованный/подменённый результат или неканонический JSON останавливают подпись.

Перед подтверждением сверяйте полный адрес, сеть, nonce, комиссию, все изменения баланса и ресурсов, полномочия и предупреждения. Подпись для операции с отдельным плательщиком комиссии может быть частичной: второй изолированный владелец должен отдельно проверить и добавить своё разрешение. Никакая частичная или полная подпись не означает отправку.

## Команды

```sh
npm run offline:verify -- request.nir.json
npm run offline:sign -- wallet.nirvault.json request.nir.json signed-package.json
npm run offline:watch-export -- wallet.nirvault.json checkpoint.json watch-only.json
```

Для входа со стандартного ввода замените `package.json` на `-`. Пароль запрашивается только с интерактивного терминала, не принимается аргументом и не записывается в файл. Подписанный и watch-only файлы создаются только как новые с правами `0600`.

Watch-only экспорт содержит лишь публичный адрес, публичный ключ и проверенный checkpoint. В нём нет зашифрованного vault, пароля или приватного ключа.

## Рабочая среда

Запускайте изолированный процесс на устройстве без сети: отключите сеть до запуска, не используйте режим отладки/инспектор и не переносите vault на сетевое устройство. Программа отказывается запускаться с активным инспектором и запрещает диагностические отчёты Node, но переносимое приложение не может надёжно запретить дамп памяти ядром ОС. Отключите core dumps средствами вашей ОС, ограничьте доступ к учётной записи и после работы выключите устройство. Очистка ключа в памяти выполняется best-effort; она не заменяет изоляцию процесса и ОС.
